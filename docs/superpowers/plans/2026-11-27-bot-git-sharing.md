# 공유 봇 패키지 작성·설치 구현 계획

이슈 [#46](https://github.com/tworimpa/ai-agent-office/issues/46)의 저장소 공유·설치 마일스톤이다. 기준 커밋은 `9dbf8b5`다. 이 문서는 구현 전 검토용이다.

## 합의한 범위

- 작성자는 로컬 Studio에서 기존 봇을 공유 패키지로 내보내고, 패키지 파일을 공개 Git 저장소에 직접 올린다.
- 설치자는 로컬 Studio에서 공개 HTTPS Git URL과 버전을 입력하고 대상 Workspace에 설치한다. 설치 후 기존 역할 배정과 의뢰 흐름을 사용한다.
- 패키지에서 `MEMORY.md`는 항상 제외한다. 설치자는 빈 메모로 시작한다. 작성자가 공유할 참고 자료는 별도 문서로 담는다.
- Windows와 WSL Ubuntu의 독립 테스트 Workspace에서 인증된 Codex로 읽기 전용 의뢰를 각각 한 번 완료한다.
- CLI 설치, 비공개 저장소, 업데이트, 롤백은 후속 범위다.

## 구현안 검토 사항

- 내보내기는 Studio에서 ZIP 한 개를 내려받는 방식으로 제안한다. 작성자는 ZIP을 풀고 파일을 Git에 올린다.
- 저장소 루트 또는 선택한 하위 폴더에 패키지를 둔다. 버전 입력은 **Git 태그 또는 전체 커밋 SHA**만 지원한다. 태그는 `refs/tags/`에서 찾는다. 설치 이력에는 입력한 버전과 실제 해석한 전체 커밋 SHA를 함께 기록한다.

## 1. 패키지 규격과 내보내기

- [ ] `plugin.json`은 Agent Plugins 1.0.0의 메타데이터와 `extensions.io.github.tworimpa.agentoffice`를 담는다. Office 전용 폴더의 `bot.json`은 기존 Bot Definition 1.0을 사용한다. 패키지 검증을 맡는 새 모듈을 `src/agent_office/bot_package.py`에 둔다. 기존 파일 경로·크기·역할 검사는 `bot_spec.py`를 재사용한다. 두 스키마와 예제 패키지의 작성법을 문서화한다. [Agent Plugins 확장 규격](https://agent-plugins.org/plugin-authors/client-extensions) · [Bot Definition 1.0](../../bot-spec-v1.md)
- [ ] `SOUL.md`, 별도로 넣은 참고 문서, 봇의 텍스트 스킬과 외형 등 공유할 정의를 보존한다. 선택적으로 루트 `skills/<name>/SKILL.md`를 담은 패키지는 봇 정의의 동일 경로에 텍스트 자원으로 가져온다. 정의 내부와 루트 스킬에 같은 경로가 있으면 모호한 덮어쓰기를 피하기 위해 검증 오류를 반환한다. Git 패키지 경로는 메모나 설치자 권한을 대체할 수 없다.
- [ ] `웹 봇 API`에 패키지 다운로드를 추가한다. 현재 저널의 저장된 정의에서 내보낼 사본을 만들고 `MEMORY.md`를 빼고 검증한 뒤 ZIP을 생성한다. 기존 `/manifest`와 JSON 가져오기·내보내기 동작을 회귀 테스트로 고정한다.
- [ ] 패키지 테스트에서 저장한 메모에 고유 문자열을 넣어 ZIP과 내부 정의에서 그 문자열과 `MEMORY.md`가 빠졌는지 검사한다. 원본 봇의 메모 보존, 한국어 지침, 중첩 파일·폴더와 확장 왕복도 검증한다.

## 2. 공개 Git 버전 확인과 Workspace 설치

- [ ] Git에서 선택한 버전을 커밋으로 해석하고 그 커밋의 패키지 파일을 읽는다. 검사와 다운로드에는 시간·용량 한도를 적용한다. HTTPS 공개 목적지만 허용하고 Git 자격 증명과 대화형 로그인에 의존하지 않는다. 연결·리디렉션에서 내부 주소 접근을 막으며, 체크아웃·서브모듈·훅 실행 없이 필요한 Git 항목만 읽는다. 링크·특수 항목과 패키지 밖 경로는 입력 오류로 처리한다.
- [ ] Studio의 기존 동일 출처·저널 확인 경계에서 미리보기와 설치를 받는다. 미리보기는 봇 이름·역할·패키지 버전·커밋·파일 목록과 정의 해시를 보여 준다. 확인 시 미리 본 커밋과 정의 해시를 검사해 같은 내용을 적용한다. 다운로드와 검증이 끝난 후 SQLite 쓰기 트랜잭션을 열고, 기존 `local_bots.install`과 같은 트랜잭션에서 URL·하위 경로·지정 버전·커밋·정의 해시를 기록한다.
- [ ] 수동으로 작성한 패키지에 `MEMORY.md`가 들어 있으면 파일을 빼고 다시 만들도록 오류를 표시하는 구현안을 적용한다. 같은 출처·커밋·정의를 다시 설치하면 기존 항목을 반환한다. 정의가 다른 동일 봇 ID는 기존 충돌 규칙을 적용한다. 출처가 다른 동일 정의로 기존 설치 출처를 덮어쓰지 않도록 한다.
- [ ] 테스트에서는 태그 해석, 존재하지 않는 버전, 미리보기 뒤 태그가 이동한 경우, 요청 중단과 재시도, 동일 ID 충돌, 손상된 정의, 접근 제한과 파일 검증 실패를 재현한다. 실패 시 봇·출처 기록의 부분 저장이 없고 기존 배정과 실행 기록을 읽을 수 있어야 한다.

## 3. 봇 회의실에 작성자와 설치자 흐름 연결

- [ ] `src/agent_office/web/bot-client.html`과 `bot-client.js`의 기존 정의 가져오기·내보내기 UI 옆에 공유 패키지 동작을 추가한다.
- [ ] 작성자 흐름은 **봇 선택 → 공유 패키지 내보내기 → ZIP 다운로드**다. 설명에는 압축을 푼 파일을 작성자가 Git 저장소에 올리는 절차와 `MEMORY.md` 처리 방식을 적는다.
- [ ] 설치자 흐름은 **Git에서 설치 → 공개 URL·버전과 선택 하위 폴더 입력 → 미리보기 → 설치 → 새 봇 열기**다. 역할을 배정하려면 기존 Workspace 설정을 사용한다. 설치 확인만으로 역할 변경이나 CLI 실행이 발생하지 않는지 확인한다. 설치한 봇의 메모는 파일 편집기에서 빈 상태로 열린다.
- [ ] DOM 테스트로 잘못된 버전 오류, 중복 요청 방지, 설치 후 새 봇 선택, 기존 JSON 버튼을 검증한다. Studio HTTP 테스트로 동일 출처와 저널 확인, 올바른 대상 Workspace, 미리보기와 확정 사이의 일관성을 검증한다. [기존 Studio API](../../bot-client.md)

## 4. 다른 Workspace에서 인수 검증

- [ ] 원본 Studio에서 업무 지침, 공개 참고 자료, 비공개 메모가 있는 예제 봇을 내보낸다. 미리보기와 설치 재현용 공개 Git 커밋을 준비한다. 공개 검증에는 테스트용 텍스트만 사용한다. 같은 패키지를 Windows와 WSL Ubuntu의 새로운 후보 Studio 저널에서 각각 UI로 설치한다. 설치한 커밋·정의 해시가 일치하고 메모가 비어 있는지 확인한다.
- [ ] 각 환경에서 설치한 봇을 개발자 자리에 배정한다. Codex로 읽기 전용 의뢰를 한 번 실행하고, 패키지의 지침과 공개 참고 자료를 읽어야 알 수 있는 결과를 확인한다. OS·CLI 버전·실행 ID·최종 상태·결과·실행에 기록된 봇 ID와 정의 해시를 남긴다. 테스트용 작업 폴더의 Git 상태도 대조한다. 인증된 CLI 실행은 시험 범위에 대한 별도 승인을 적용한다.
- [ ] Windows에서는 `.venv\Scripts\python.exe scripts\quiet_pytest.py`로 패키지·봇 API·기존 정의 회귀를 확인한다. Linux의 해당 pytest와 웹 DOM 테스트도 실행한다. 공개 Git과 인증된 Codex 인수 결과는 모의 테스트와 각각 기록한다. [기존 읽기 전용 실사용 기록](../../bot-room-live-verification.md)
