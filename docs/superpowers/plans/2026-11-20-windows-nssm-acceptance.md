# Windows NSSM 배포 검증 계획

1. GitHub-hosted Windows 3.13 작업에서 NSSM 원본 64비트 바이너리의 SHA-256을 대조한다. 임시 SCM 서비스마다 고유 이름과 전용 가상 계정 `NT SERVICE\<서비스 이름>`을 지정한다. 서비스 계정에는 배포 원장과 소스의 읽기 권한, 런타임 저널과 로그 디렉터리의 쓰기 권한을 준다.
2. 임시 Git 원장에서 구문 검사를 통과한 세 버전을 준비한다. Windows ConPTY의 운영자 확인 절차로 1번을 배포하고 2번으로 재시작한다. 새 부팅 ID, 서비스 계정 SID, 버전별 자산을 대조한다.
3. 3번은 Studio 시작에서 실패하도록 만든다. 배포 CLI의 실패 종료, NSSM 로그의 의도한 실패 원인, 2번의 새 부팅 ID와 자산을 확인한다. 안정 원장에는 승인한 3번이 유지된다.
4. 실제 Edge가 관제 Studio의 안정 버전 화면을 열어 대상 3번과 실제 실행 2번의 커밋 차이, 복구 완료 상태를 표시하는지 확인한다. 시험이 끝나면 등록한 서비스만 중지하고 삭제한다. 일반 로컬 테스트에는 이 SCM 시험을 포함하지 않는다.
