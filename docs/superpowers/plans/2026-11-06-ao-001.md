# AO-001 Persistent Tasks and Events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 종료 후에도 작업 상태와 단계별 실행 이력을 조회하고, 중단된 작업을 자동 재실행 없이 식별한다.

**Architecture:** 별도 SQLite task/run/event 저장소를 durable truth로 두고 현재 LangGraph 노드에 기록기를 주입한다. run별 OS 잠금과 명시적 recover로 살아 있는 작업을 보호한다. 자동 checkpoint resume와 서버/UI는 추가하지 않는다.

**Tech Stack:** Python 3.11+, stdlib sqlite3/fcntl/msvcrt, 기존 LangGraph 1.x, pytest, Windows/Linux.

**Spec:** [AO-001 설계안](../specs/2026-11-06-ao-001-design.md). 사용자 검토용이며 아직 구현/실행 승인을 받은 것으로 간주하지 않는다.

**Acceptance:** [명령·JSON·수용 A01–A14](../specs/2026-11-06-ao-001-acceptance.md). 오류 코드, cursor 응답, 정상 이벤트 순서와 실패 시 호출 횟수는 이 계약을 따른다.

**Delivery:** [개발 묶음과 AO-002~004 시연 목표](2026-11-06-delivery-roadmap.md).

## Global Constraints

- Windows/Linux 동등 지원, Python 3.11+, CI Windows/Ubuntu × Python 3.11/3.13 유지.
- 신규 런타임 의존성은 추가하지 않는다. 단일 호스트의 로컬 디스크 DB만 지원한다.
- `PLAN_ONLY`는 테스트나 리뷰 통과를 뜻하지 않는다. 기존 CLI `status` 의미를 유지한다.
- 시작 기록이 실패하면 외부 작업을 실행하지 않는다. 결과 기록이 실패하면 다음 단계/성공 보고를 금지한다.
- IDs는 UUID hex 32자리, 시간은 UTC ISO 8601, busy_timeout=5000, schema user_version=1.
- request_snapshot UTF-8 8,192 bytes, payload JSON UTF-8 16,384 bytes. 자동 삭제는 없다.
- 원본 prompt/source/stdout/stderr/환경변수/provider session/token을 이벤트에 저장하지 않는다.
- 구현은 `main`과 다른 branch/worktree/DB에서 진행한다. 자동 merge/push/deploy/권한 변경은 추가하지 않는다.

## Review Focus

1. 두 coordinator의 동시 claim/복구가 살아 있는 run을 중단된 것으로 바꾸지 않는가 — Task 1/3.
2. 외부 작업과 DB commit 사이의 crash가 재실행·완료 오판을 만들지 않는가 — Task 4.
3. 요청·오류·중첩 payload와 한글이 기록 한도를 우회하거나 비밀 원문을 남기지 않는가 — Task 2.
4. 누락/잘못된 DB나 버전·읽기 전용/잠긴 DB가 원본을 변경하거나 외부 작업을 시작하지 않는가 — Task 1/4/5.
5. 상충 리뷰·CLI 실패·계획 전용 결과가 승인/완료로 저장되지 않는가 — Task 0/4.

## 파일과 공통 인터페이스

| 파일 | 책임 |
|---|---|
| `models.py` (신규) | TaskSpec, TaskRecord, RunRecord, EventRecord, OwnerInfo 및 상태/결과 타입 |
| `store.py` (신규) | schema, 짧은 원자적 transaction, idempotency, 읽기 연결 |
| `events.py` (신규) | allowlist/마스킹/byte 한도, RunRecorder |
| `ownership.py` (신규) | run lock과 명시적 recover |
| `runtime_paths.py` (신규) | OS별 stable 기본 DB 경로, 명시 경로 해석 |
| 기존 `workspace.py`, `workflow.py`, `cli.py` | worktree intent, 단계 기록, 실행/조회 진입점 |

위 신규 모듈의 경로는 모두 `src/agent_office/` 아래다. 타입 필드는 설계의 저장 테이블과 동일한 이름을 사용한다. `TaskSpec(task_id, project, request_snapshot, developer_engine, reviewer_engine, max_attempts)`, `OwnerInfo(host_name, owner_token)`은 frozen dataclass다. 기존 `workspace.Worktree(path: Path, branch: str)`를 실행 전 intent와 생성 결과에 함께 사용한다.

## Task 1: SQLite task/run/event 저장 계약

**Files:** Create `src/agent_office/models.py`, `src/agent_office/store.py`, `tests/test_store.py`.

**Interfaces:**

```text
TaskStore(db_path: Path, *, readonly: bool = False) [context manager]
create_run(spec: TaskSpec, run_id: str, intent: Worktree, owner: OwnerInfo) -> RunRecord
record_transition(run_id: str, *, operation_key: str, event_type: str,
                  state: str | None = None, outcome: str | None = None,
                  attempts: int | None = None, payload: dict | None = None) -> EventRecord

list_tasks(*, limit: int = 50) -> list[TaskRecord]
list_events(task_id: str, *, run_id: str | None = None,
            after_seq: int = 0, limit: int = 100) -> list[EventRecord]
```

## 실행 순서와 완료 판정

권장 순서는 Task 0 → 1 → 2 → 3 → 4 → 5다. 공유 저장 계약에 의존하므로 한 구현자가 순차 진행하고, 전체 변경을 독립 리뷰하는 방식을 우선 추천한다. 필요하면 독립적인 실패 주입/OS 검증은 병렬로 분담한다.

완료는 모든 요구사항을 실제 DB 파일/fake subprocess/두 OS CI 근거로 확인했을 때만 선언한다. 실제 Claude/Codex 인증·읽기 호출·편집 모드 수용은 별도 항목이며 이 계획의 테스트 통과로 대체하지 않는다.
