# 작업 이력 기반 개선안과 안정 소스 승격 구현 계획

[제품 구상 4단계](../../product-vision.md)를 구현한다. Windows와 Linux의 작업 에이전트는 선택된 실행을 근거로 패치를 제안한다. 운영자는 별도 릴리스 디렉터리에서 정확한 후보와 회귀 결과를 검토하고 승인한다.

## 작업 순서와 검증 기준

1. `improvement_proposal.py`에서 저널의 완료된 실행을 선택해 요청·상태·단계 근거를 묶는다. 기준 커밋의 독립 복사본에서 기존 CLI 어댑터를 읽기 모드로 호출해 근거, 기대 효과, 패치를 JSON으로 내보낸다. 생성한 제안 전체의 해시를 원본 저널에 기록하고 접수 때 읽기 전용으로 대조한다. 잘린 응답, 다른 실행 인용, 근거 없는 제안, 빈 패치를 거절한다.
2. `release_store.py`에서 운영자 전용 릴리스 디렉터리에 안정 소스와 불변 후보를 보관한다. 기준 커밋과 후보 SHA를 연결하고 검증 결과와 사람의 결정을 기록한다. 승격·거절의 재시도와 경합을 시험하고, 기준이 바뀐 후보는 새 기준으로 다시 제안하도록 한다.
3. `release_validation.py`에서 후보 커밋의 소스 아카이브를 지정한 검사 이미지에 전달한다. 네트워크와 호스트 쓰기 접근을 차단하고 시간·자원 한도 안에서 고정 회귀 검사를 수행한다. 이미지·커밋·종료 상태·출력을 기록하며 실패·중단·시간 초과는 승격 대상에서 제외한다.
4. `agent-office improve` 명령으로 제안·접수·검증·검토·승인·거절·안정 소스 추출을 연결한다. 사람의 승인은 검토한 SHA를 지정하고 운영자 터미널에서 확인한다. 작업자에게 릴리스 디렉터리 쓰기 권한을 주지 않는다. 이미 실행 중인 서비스의 배포는 운영자가 따로 관리한다.
5. 임시 Git 저장소와 모의 CLI로 전체 경로, 변경된 기준과 중복 결정, 실패한 검증을 시험한다. Linux에서는 실제 컨테이너 회귀 검사를 추가로 확인한다. Windows·Ubuntu CI와 병합 결과를 확인한다.
