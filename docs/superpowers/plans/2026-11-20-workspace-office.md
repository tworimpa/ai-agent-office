# Workspace 사무실 구현 계획

Workspace를 선택하고 조정자에게 일을 맡긴 뒤, 담당자 초상화에서 진행 상황과 결과를 확인하며 같은 작업을 이어간다.

## Workspace와 배정

- 호스트별로 Workspace의 에이전트 이름, 역할별 엔진과 스킬 버전, 기술 질문 위임 기본값을 저널에 저장한다. 기존 Workspace를 그대로 열 수 있게 기본 설정을 제공한다.
- `GET /api/rooms/{workspace_id}`로 설정과 해당 Workspace의 실행을 읽고 `POST`로 설정을 저장한다. `POST /api/rooms/{workspace_id}/assignments`는 요청 ID, 원문, 수정 허용 여부, 선택적 폴더 범위와 위임 재정의를 받는다. 한 체크아웃 안에서는 등록된 폴더를 기본 범위로 쓰고, 필요한 경우 작업 폴더를 명시한다.
- 조정자가 호스트에서 사용할 수 있는 엔진 중 역할에 맞는 엔진을 결정한다. 사용자 요청과 배정 근거, 실제 적용된 역할과 위임 값을 실행과 함께 저장한다. 응답이 끊긴 뒤 동일 ID로 재시도해도 같은 배정이 반환되어야 한다.

## 대화와 질문

- 담당자에게 보내는 추가 지시는 `GET/POST /api/runs/{run_id}/directions`로 조회·등록한다. 현재 단계와 대화에 묶어 전달하고 대기·전달·전달 불확실·미전달 상태를 기록한다. 같은 지시를 여러 번 실행하거나 종료된 단계로 보내는 상황을 검증한다.
- 작업의 위임 설정이 켜져 있고 기준 커밋에서 확인 가능한 기술 질문은 전문 에이전트와 검증 절차로 처리한다. 기존 구현, 진단 시작 위치, 기존 테스트 중 하나를 선택할 때 담당자가 범위 안에서 기준 커밋의 위치 2~4개를 제시한다. 두 역할이 같은 선택과 인용에 동의한 경우에만 결정한다. 제품 동작 결정과 권한 요청은 사용자 응답을 받는다. 응답과 위임 근거를 원래 실행의 대화에 표시한다.

## 사무실과 검증

- Studio 기본 화면에서 Workspace를 골라 작업을 맡기고, 초상화 옆에서 저널에 기록된 단계와 미응답 요청을 확인한다. 초상화 또는 이력에서 같은 실행의 대화, 결과, 변경 및 검증 내역을 연다. 기존 상세 설정과 관리 화면은 `/studio`에서 접근할 수 있게 한다.
- 원격 요청은 기존 SSH 저널 식별 경로를 사용한다. 로컬 및 원격의 작업 배정, 응답 유실 후 재시도, 재연결, 종료된 작업 이력, 위임 범위, 질문 응답 및 검증 내역을 모의 CLI와 실제 브라우저로 확인한다.
- 프로젝트 지침에 따라 Windows/Linux 전체 CI를 최신 PR 커밋에서 확인하고, 해결되지 않은 차단 리뷰가 없으면 동일 SHA를 지정해 머지한다.
