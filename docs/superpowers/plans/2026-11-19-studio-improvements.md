# 작업실 개선안 생성·검토 구현 계획

제품 4단계의 개선 절차를 호스트별 작업실에서 시작하고 추적한다. 운영자 터미널이 안정 소스 승격을 전담한다.

1. 작업 호스트 저널에 선택한 종료 실행, 기준 SHA, 제안 엔진, 생성 상태와 결과를 보존한다. 같은 요청을 재전송하면 같은 작업을 돌려주고, 끊긴 생성 작업은 유료 엔진을 자동 재실행하지 않는다.
2. 운영자 명령이 원본 저널의 생성 기록과 패치를 대조해 후보를 접수하고 격리 검증한다. 후보 SHA·실제 diff·검증 결과·결정 이력을 운영자가 관리하는 별도 조회 DB에 게시한다. Studio에는 조회 DB와 기준 소스만 제공한다.
3. 로컬·SSH 작업실에서 같은 개선안 화면을 사용한다. 사용자는 종료된 실행을 선택해 제안하고, 생성 내역에서 후보 상세로 이동해 검증과 터미널 결정을 확인한다. 마지막 게시 시각과 연결 오류를 표시한다.
4. 운영자 권한 경계를 HTTP 경로와 SSH 허용 목록에서 검사한다. 모의 CLI, 실제 임시 Git과 SQLite, 브라우저, Windows·Ubuntu CI로 중복 요청, 재접속, 후보와 결정의 연결을 확인한다.

## 운영과 복구

- Studio는 시작 시 설정한 소스 체크아웃과 조회 파일만 사용한다. 브라우저는 생성 요청에 실행 ID, 엔진과 게시된 기준 SHA를 보낸다. 조회 파일은 운영자가 별도 디렉터리에 만들고 작업실은 읽기 전용으로 연다.
- 운영자의 `studio-sync`는 해당 저널의 생성 기록을 대조한 후보만 게시한다. 다른 작업실의 저널이나 다른 릴리스의 조회 파일과 섞이지 않도록 식별자를 확인한다. `--watch`로 터미널에서 내린 결정도 화면에 반영한다.
- 서버는 진행 중인 생성 작업과 재시작 뒤의 중단 상태를 기록한다. 사용자에게는 제안 패치와 검증된 커밋의 차이, 마지막 게시 시각, 검증·결정 이력의 표시 범위를 각각 보여준다.
