# 공유 봇 카탈로그와 CODE-Skills 연계 구현 계획

[이슈 #46](https://github.com/tworimpa/ai-agent-office/issues/46)의 **공유 봇 카탈로그·CODE-Skills 연계** 항목이다. 기준 커밋은 **3821477**이다. CODE-Skills는 회사의 스킬 공유 시스템이다. 검색·상세·설치 동선은 [skills.sh](https://skills.sh/docs)를 참고한다.

## 합의한 사용자 흐름

1. Agent Office Studio의 봇 회의실에서 **봇 카탈로그**를 연다.
2. 이름·역할·태그로 봇을 찾는다. 상세에서 게시자, 설명, 포함 스킬, 공개 Git 저장소와 배포 커밋을 확인한다.
3. 포함 스킬의 **CODE-Skills에서 보기**를 눌러 회사 시스템의 해당 스킬 상세 페이지를 연다. 링크는 등록자가 실제 상세 주소를 제공한다.
4. **설치 미리보기**로 현재 Workspace의 기존 package-preview 흐름을 연다. 호스트가 실제 패키지와 커밋·정의 해시를 검증한다. 사용자가 확인한 뒤 기존 package-install로 설치한다. [현재 Studio 설치 API](../../bot-client.md)

## 1. Git 목록 게시와 등록 계약

- [ ] 버전 있는 JSON 목록 형식과 검증 예제를 작성한다. 항목의 필수 정보는 카탈로그 ID, 봇 ID, 게시자, 이름, 역할, 설명, 태그, 공개 HTTPS Git URL, 전체 커밋 SHA다. 패키지 하위 경로, 사람이 읽는 버전명과 포함 스킬 목록을 제공할 수 있다.
- [ ] 포함 스킬은 패키지 내부의 스킬 경로와 표시 이름을 기록한다. CODE-Skills 등록이 있는 스킬은 실제 HTTPS 상세 URL을 함께 기록한다. 같은 이름의 여러 스킬도 패키지 경로와 상세 주소로 구별한다.
- [ ] 등록 검증은 기존 Git 패키지 검사와 Bot Definition 1.0을 사용한다. 카탈로그에 적힌 봇 ID와 포함 스킬은 고정 커밋의 패키지와 대조한다. 중복 ID, 잘못된 버전과 누락된 출처를 보고한다.
- [ ] 카탈로그 목록은 기존 `tworimpa/ai-agent-office` 저장소의 `catalog/bots.json`에 둔다. 등록자가 목록 변경을 이 저장소의 PR로 제출하면 운영자가 패키지 커밋과 스킬 상세 링크를 검토한다. `main`에 병합된 목록은 앱 릴리스와 별도로 게시된다.
- [ ] 목록의 게시 리비전과 각 봇의 설치 커밋을 구분한다. 같은 목록 리비전에 여러 패키지 커밋을 실을 수 있다. 검색 결과에서 선택한 패키지는 해당 항목의 전체 커밋 SHA로 검증한다.

## 2. Studio 카탈로그와 설치 연결

- [ ] Studio 호스트가 [`main`의 카탈로그 JSON](https://raw.githubusercontent.com/tworimpa/ai-agent-office/main/catalog/bots.json)을 공개 HTTPS로 읽고 스키마를 검증한다. 카탈로그를 열거나 새로고침할 때 게시된 목록을 조회하는 구현안을 적용한다. 읽기 실패나 잘못된 목록은 카탈로그에 표시하고 다시 시도할 수 있게 한다.
- [ ] **봇 카탈로그**에 검색과 상세 보기를 추가한다. 한글·영문 검색, 태그와 결과 없음 상태를 검증한다.
- [ ] 상세에서 패키지 출처와 고정 커밋을 보여 준다. **설치 미리보기**는 해당 항목의 URL·경로·전체 커밋 SHA를 기존 화면에 전달한다. 카탈로그에서 고른 커밋과 실제 응답의 커밋 및 봇 ID를 비교한다. 다르면 목록이나 패키지를 다시 확인하도록 안내한다.
- [ ] 설치 대상으로 현재 Workspace를 표시한다. 확인 버튼으로 기존 설치 동작을 실행한다. 이미 설치된 봇은 현재 저장소·경로·커밋을 보여 준다.
- [ ] 카탈로그가 동일 출처에 다른 배포 커밋을 제시하면 비교할 버전을 표시한다. 사용자가 선택하면 기존 업데이트 미리보기·충돌 검사·한 단계 롤백을 사용한다.

## 3. CODE-Skills 상세 링크

- [ ] 스킬 상세 링크와 패키지 내부 스킬 경로를 함께 표시한다. CODE-Skills 내부 검색 API 호출은 이 흐름에 필요하지 않다. 접근이 필요한 상세 페이지는 외부 브라우저의 회사 로그인 세션으로 연다.
- [ ] 웹 Studio에서는 게시 목록의 HTTPS 상세 URL을 검증하고 브라우저에서 연다. Electron과 Rust 비교판은 현재 Studio의 등재 링크 경로를 시스템 브라우저에 넘긴다. CODE-Skills 연결 시험에는 시험용 HTTPS 상세 링크를 사용한다.
- [ ] 상세 링크를 열어도 현재 Workspace, 저널 식별자, 로컬 봇 파일과 설치 설정은 외부 요청에 포함하지 않는다.

## 4. 인수 검증

- [ ] 공개 목록에 검증 가능한 예제 패키지를 등록한다. 후보 Studio의 시험 목록에 시험용 상세 URL을 넣어 Windows와 WSL Ubuntu에서 검색 → 상세 → 포함 스킬 링크 → 설치 미리보기 → Workspace 설치를 확인한다.
- [ ] 같은 앱에서 Git 목록에 게시한 새 항목과 새 배포 커밋이 새로고침 뒤에 표시되는지 확인한다. 설치 미리보기는 항목에 기록된 정확한 패키지 커밋을 검증한다.
- [ ] 항목과 실제 패키지의 봇 ID가 다른 경우, 목록을 읽지 못한 경우, 잘못된 상세 URL, 동일 커밋 재설치, 설치한 봇의 다른 배포 커밋 선택을 검증한다.
- [ ] Windows·Linux CI와 실제 후보 Studio 흐름의 증거를 PR에 남긴다. 설치된 정의가 새 의뢰에 기록되는지는 기존 모의 CLI로 확인한다.
