# 공유 봇 업데이트와 한 단계 롤백 구현 계획

[이슈 #46](https://github.com/tworimpa/ai-agent-office/issues/46)의 **업데이트와 운영** 마일스톤 중 Studio 업데이트와 롤백 범위다. 기준은 공유 패키지 설치가 병합된 커밋 **a871585**다. [공유 패키지 사용법](../../local-role-bots.md#공개-git-저장소에서-공유하기)

## 합의한 동작

- Studio의 설치된 봇에서 같은 공개 HTTPS 저장소의 새 **Git 태그 또는 전체 커밋 SHA**를 직접 입력한다. 현재 버전과 후보 버전의 실제 커밋, 정의 해시, 변경 내용을 확인한 뒤 적용한다.
- 업데이트와 롤백 모두 서로 겹치지 않는 로컬 편집을 유지한다. 같은 파일에 적용할 내용이 서로 다르면 경로를 보여 주고 전체 작업을 중단한다. 파일별 버전 선택은 다음 단계다.
- 업데이트 직전 상태 한 번을 로컬에 보관한다. 이후 업데이트는 복원 대상을 직전 상태로 바꾼다. 롤백에 성공하면 한 단계의 복원 기회를 사용한다. 원격 Git 연결 없이 복원할 수 있다.
- 같은 봇 ID와 Workspace 배정을 사용하고, 개인 메모와 호스트의 엔진·권한 설정을 보존한다. 새 의뢰는 변경 후 정의를 쓰고 이미 접수된 실행은 저널에 고정한 정의를 계속 사용한다.

## 비교 규칙

| 경우 | 적용 결과 |
| --- | --- |
| 로컬에만 변경이 있음 | 로컬 변경을 유지한다. |
| 배포본에만 변경이 있음 | 추가·수정·삭제를 적용한다. |
| 양쪽이 동일한 결과로 바뀜 | 그 결과를 사용한다. |
| 양쪽이 같은 파일을 서로 다르게 바꿈 | 경로를 표시하고 적용을 중단한다. 수정과 삭제가 겹치는 경우도 포함한다. |
| 파일과 폴더가 같은 경로를 차지하거나 대소문자만 다른 이름이 생김 | 관련 경로를 표시하고 적용을 중단한다. |

업데이트는 **현재 배포본 원본**, **현재 로컬 정의**, **후보 배포본**을 비교한다. 봇 이름·표시 역할·확장 같은 메타데이터도 항목별로 비교한다. 로컬 외형과 배포본 외형이 충돌하면 해당 설정을 표시한다. 파일은 전문을 비교한다.

롤백은 **업데이트 직후의 로컬 정의**, **현재 로컬 정의**, **업데이트 직전의 로컬 정의**를 비교한다. 업데이트 전 로컬 편집과 업데이트 이후의 겹치지 않는 편집을 모두 보존할 수 있다. 복원 후 배포본 원본과 Git 출처도 직전 버전으로 돌아간다. 개인 메모는 버전 비교와 복원용 복사본에서 제외하고, 적용 시점의 로컬 메모를 결과에 넣는다.

## 1. 비교 기준 저장과 기존 설치본 처리

- [ ] Git 설치 성공 시 출처와 배포본 원본을 Workspace 저널에 함께 저장한다. 기존 출처의 정의 해시는 배포본 원본을 가리킨다. 로컬 편집을 포함한 현재 봇 정의 해시는 별도로 확인할 수 있다.
- [ ] PR #52에서 설치한 봇은 기존 기록의 정의 해시로 원본을 확인한다. 메모를 빼고 계산한 현재 정의 해시가 일치하면 현재 로컬 정의에서 원본을 복구할 수 있다. 다르면 저장된 URL·패키지 경로·**전체 커밋 SHA**로 원본을 가져와 커밋과 해시를 모두 검증한다. 검증된 원본을 확보할 수 없으면 미리보기에서 이유를 표시한다.
- [ ] 한 단계 복원에 필요한 직전 배포본과 출처, 변경 직전·직후 로컬 정의를 저장한다. 저장과 읽기에는 기존 Bot Definition 검증기와 파일 경로 규칙을 사용한다.
- [ ] 기존 저널, 원격 태그 이동, 원본 커밋 연결 실패, 해시 불일치, 메모만 바뀐 기존 설치본을 각각 테스트한다. [현재 저장 형식과 API](../../bot-client.md)

## 2. 업데이트·롤백 적용

- [ ] 별도 비교 함수에서 파일과 메타데이터 변경 및 충돌을 계산한다. 기존 Bot Definition 1.0 검증으로 조합 후 경로·형식·크기 제한도 확인한다. 결과는 변경 요약과 충돌 경로 또는 검증을 통과한 정의다.
- [ ] Bot API에 업데이트 미리보기·적용과 롤백 미리보기·적용을 추가한다. 동일한 저장소·하위 폴더·봇 ID를 확인하고, 업데이트에는 선택한 태그나 커밋을 기존 공개 Git 읽기 경로로 해석한다.
- [ ] 적용 시 미리보기에서 본 현재 버전과 메모를 제외한 로컬 정의 해시를 다시 확인한다. 다른 창의 파일 편집이나 태그 이동으로 미리보기의 전제가 바뀌면 다시 확인하도록 안내한다. 메모만 바뀐 경우에는 적용 시점의 메모를 유지한다.
- [ ] 봇 정의, 설치 출처, 복원 상태의 변경을 하나의 SQLite 트랜잭션에서 처리한다. 같은 버전 재요청과 응답 유실 뒤 재시도에서 복원 상태가 중복 생성되지 않게 한다. 충돌·오류·중단 시 현재 봇과 복원 상태가 보존되는지 확인한다.

## 3. Studio 연결

- [ ] 봇 회의실의 **Git 설치 출처**에서 현재 태그·커밋·정의 해시와 복원 가능한 직전 버전을 표시한다.
- [ ] **업데이트 확인**에서 태그나 전체 SHA를 직접 입력한다. 현재·후보 커밋을 비교하고 추가·수정·삭제 경로와 유지되는 로컬 편집을 확인한 뒤 적용한다. 충돌하면 파일 경로를 표시하고 적용 버튼을 비활성화한다.
- [ ] **직전 버전으로 롤백**에서 복원할 커밋과 변경을 확인한다. 롤백 충돌도 같은 방식으로 표시한다. 적용 성공 뒤 봇 목록과 열려 있는 편집 화면을 기존 정의 해시 갱신 동작으로 새로 고친다.
- [ ] DOM과 Studio HTTP 테스트로 다른 Workspace의 상태 격리, 더블 클릭, 오래된 미리보기, 편집 충돌 이후 새로고침을 검증한다.

## 4. 인수 검증과 PR

- [ ] Windows와 WSL Ubuntu의 후보 Studio에서 공개 예제를 설치한다. 새 태그 또는 커밋을 적용하고, Git 접근을 끊은 상태에서 직전 상태로 롤백한다. 유지된 메모·로컬 파일, 실제 커밋·해시, Workspace 배정을 대조한다.
- [ ] 업데이트 전·후·롤백 후 새 의뢰에 고정된 정의를 모의 CLI 입력과 실행 기록에서 각각 대조한다. 이전에 접수한 실행의 해시를 다시 조회한다. 로컬·배포본 수정 충돌과 업데이트 후 발생한 롤백 충돌을 따로 재현한다.
- [ ] Windows의 관련 pytest는 숨은 실행 래퍼를 사용한다. PR 최신 커밋의 Windows·Linux Python 테스트와 데스크톱·Rust 비교 검사, 차단 리뷰를 확인한 뒤 예상 헤드 SHA로 병합한다.
