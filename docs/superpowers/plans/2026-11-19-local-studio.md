# 1단계 로컬 작업실 구현 계획

**목표**는 Windows와 Linux에서 브라우저로 로컬 작업공간을 등록하고 작업을 시작·중지한 뒤, 같은 주소에서 진행 상태와 검토 결과를 다시 여는 것이다. 기준은 [제품 구상](../../product-vision.md)의 1단계다.

| 작업 | 구현 위치와 결정 | 확인할 동작 |
| --- | --- | --- |
| 작업공간 등록 | `studio_catalog.py`가 이름과 순서 있는 폴더 목록을 SQLite에 저장한다. 실행은 선택한 같은 저장소 폴더들을 하나의 worktree로 매핑한다. | 공백·한글 경로, 중복·없는 경로, 복수 저장소 선택, 재시작 후 목록 복원 |
| 실행과 중지 | `studio_runner.py`가 ID별 실행을 소유한다. 기존 개발·테스트·리뷰 그래프와 작업 기록을 재사용한다. 계획 모드를 기본값으로 두고 수정을 명시적으로 선택한다. | 원본 파일 보존, 실행 중 브라우저 종료, 중지 요청과 실제 종료 구분, 종료 후 결과 재조회 |
| 로컬 HTTP | `studio_server.py`와 `agent-office studio`를 추가한다. 기존 읽기 전용 `serve`와 분리하고 루프백·동일 출처에서 등록과 실행을 받는다. | 다른 출처의 요청 거부, 요청 중복 방지, 새 데이터베이스에서 첫 작업 시작 |
| 브라우저 | `web/studio.*`에 작업공간 등록, 폴더 선택, 작업 입력, 실행 목록·결과를 연결한다. | 한 화면에서 시작·중지·조회, 새로 고침 후 같은 실행 선택, 테스트 실패와 리뷰 결과 구분 |

실행 순서는 작업공간과 실행기 계약 확정, HTTP·화면 통합, 모의 CLI로 전체 흐름 검증, Windows·Ubuntu CI 순이다. 운영 중인 서비스와 분리된 작업 경로에서 시험한다. 실제 제공자 검증은 OS·실행파일·실제 작업 결과별로 기록하며 별도 승인 범위를 따른다.

## 구현한 동작과 검증 경로

- 폴더 등록 순서는 작업공간별로 보존한다. 각 실행은 주 폴더를 첫 항목으로 기록한다. 개발자와 리뷰어에게는 같은 worktree 안의 경로를 전달하고 테스트는 그 저장소 루트에서 실행한다. 작업공간 목록은 저널 옆의 `.studio.sqlite3` 파일에, 실행 상태와 결과는 저널에 보관한다.
- 화면은 요청마다 실행 ID를 발급한다. 접수 응답이 유실돼도 같은 ID로 결과를 확인한다. 작업 중 창을 닫아도 실행은 계속되며, 상세 주소에는 해당 ID가 남는다. 같은 데이터베이스를 사용하는 작업실 서버는 한 번에 하나만 실행한다.
- 명시적 중지와 서버의 정상 종료는 담당 실행기에 중지를 요청한다. Windows에서는 Job Object에 자식 프로세스를 넣고 시작한다. Linux에서는 실행별 감독 프로세스가 고아가 된 자손까지 회수한다. 종료 확인과 결과 기록 뒤에 최종 상태를 표시한다. 서버가 비정상 종료돼 상태가 불명확한 실행은 복구 대상으로 남긴다.
- 개발자 응답, 테스트·리뷰 결과와 Git 미리보기는 크기를 제한해 저장한다. 변경 파일 목록에는 새 파일도 포함한다. 파일 미리보기가 생략되거나 잘린 경우에는 상세 화면에 표시된 worktree에서 파일 전체를 검토한다.
