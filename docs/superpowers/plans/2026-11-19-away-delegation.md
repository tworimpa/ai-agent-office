# 3단계 구현 계획 · 부재중 기술 답변과 복귀 보고

운영자가 작업을 시작할 때 정한 기술 질문에 한해서만 전문가가 근거를 찾아 답한다. 실행 호스트가 위임 정책과 결정을 소유한다. [제품 구상](../../product-vision.md)

| 작업 | 구현 결정 | 통과 기준 |
| --- | --- | --- |
| 사전 위임 | 기본값은 꺼짐이다. 실행별로 허용할 질문, 저장소 상대 근거 파일, 전문가·독립 검증자 엔진을 지정한다. | 이전 작업은 사람에게만 질문하며 같은 실행 ID로 위임 범위를 바꾸는 재접수는 거부된다. |
| 근거 확인 | 허용된 질문과 정확히 일치할 때 기준 커밋의 파일을 읽고, 전문가가 답과 출처를 제시한다. 별도 세션의 검증자가 판단하고 코드가 인용·답의 유효성을 확인한다. | 근거 없음·불일치·모호함·공급자 실패는 답변을 생성하지 않고 사용자 대기로 남긴다. 권한 요청은 위임 경로에 들어가지 않는다. |
| 결정 기록 | 사용자와 대리 답변은 같은 호스트·실행·요청의 원래 전달 경로를 사용한다. 사용자 응답·위임 종료·세션 만료와 대리 결정의 경합은 저널 안에서 판정한다. | 끝난 위임이나 이미 처리된 요청에 늦은 답을 보낼 수 없고, 재연결 시에도 같은 답을 두 번 보내지 않는다. |
| 복귀 보고 | 호스트별 대리 결정과 근거, 작업 결과, 사람의 답이나 승인을 기다리는 요청을 함께 보여준다. | 두 호스트의 이력이 분리되고, 원격 화면을 다시 열어도 어떤 질문에 누가 답했고 무엇이 남았는지 확인할 수 있다. |

검증은 Windows·Linux의 독립 예제 저장소와 모의 CLI로 진행한다. 계정에 로그인한 실제 제공자 호출은 별도 승인 범위다.

## 결정이 확정되는 시점

전문가와 독립 검증자는 기준 커밋에서 추출한 근거를 서로 다른 임시 저장소와 세션에서 검토한다. 두 결과가 같은 사실과 출처를 지목해도 아직 제안 상태다. 원래 세션에 답을 보낼 때 호스트가 정책·요청 종류·작업 시도·세션을 다시 확인한다. 그 전에 위임 종료나 사용자 응답이 접수되면 제안은 폐기하고 **원래 요청**에서 사람의 답을 받는다. 전송을 시작한 후 결과를 확인하지 못한 경우에는 결정과 전달 미확인 상태를 함께 남긴다.

| 검증 항목 | 근거 |
| --- | --- |
| 현재 테스트 지침과 과거·조건부 예시 구분, 구성 파일의 실제 값·인용 위치, 두 역할의 독립된 검증 | [근거와 전문가 테스트](../../../tests/test_away_expert.py) |
| 사용자 결정 우선, 권한 요청 제외, 위임 해제·만료, 이전 결정의 원문 근거 보존 | [요청함 저널 테스트](../../../tests/test_studio_inbox.py) |
| 전송 직전 위임 해제 후 다섯 엔진 모두 동일한 세션·요청에서 사람 답변 사용 | [원래 세션 재개 테스트](../../../tests/test_away_continuation.py) |
| SSH 피어 경로의 대리 결정·복귀 보고, 진행 중 검토 취소와 자손 종료 | [작업실 통합 테스트](../../../tests/test_away_http.py) |

Windows Edge와 Windows 기본 OpenSSH를 통해 같은 PC의 WSL Ubuntu 피어에 접속하는 수동 시험도 수행했다. 각 호스트의 시험 저널에서 대리 결정과 남은 권한 요청을 확인했고, 위임 종료 뒤에는 같은 기술 질문에 사람이 답했다. 공급자 역할에는 모의 CLI를 사용했다.
