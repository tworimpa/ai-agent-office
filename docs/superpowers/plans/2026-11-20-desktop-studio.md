# AI Agent Office 데스크톱 앱 구현 계획

> **실행 방식**
>
> 기존 Studio 경로에 작은 변경을 추가하면서 Windows와 Linux의 설치 결과를 각각 확인한다.

**목표**

두 운영체제에서 앱 아이콘으로 작업실을 열고, 기존 작업실 연결이나 새 로컬 작업실 시작을 선택할 수 있다. 창을 닫았다 다시 열어도 같은 실행을 다시 확인한다.

**구조**

Electron은 첫 실행 화면, 연결 관리, 창과 운영체제 메뉴를 담당한다. Python Studio는 작업공간, 에이전트, 저널, SSH 연결을 기존과 같은 코드로 관리한다. 설치판에는 재배치 가능한 CPython과 의존성을 포함한다.

**선택 근거**

Electron은 Windows와 Linux에서 같은 브라우저 엔진으로 이미 검증 중인 Studio 화면을 사용한다. Tauri는 설치 파일이 가벼운 대신 운영체제별 웹뷰와 Rust 빌드의 추가 검증이 필요하다. 브라우저 바로가기는 창을 닫은 뒤 작업을 이어가는 로컬 실행기 관리와 설치 환경 구성이 필요하다.

## 단계별 산출물

- [ ] `src/agent_office/desktop_runtime.py`의 로컬 실행기가 루프백 주소를 할당하고 기존 Studio 저널을 사용한다. 부팅 식별자와 실제 응답으로 연결을 확인하며, 앱의 종료 요청은 일치하는 로컬 실행기에만 적용한다.
- [ ] `desktop/`의 앱이 두 시작 모드, 최근 작업 화면 복원, CLI 상태 및 오류 안내를 제공한다. 내장 화면은 필요한 동작만 운영 프로세스에 요청하고, Studio 창은 브라우저 샌드박스 내에서 실행한다.
- [ ] Windows x64 사용자별 설치 실행 파일과 Ubuntu/Debian 계열 x64 설치 패키지를 같은 소스에서 만든다. 수동 업데이트와 제거 과정에서 사용자 데이터 경로를 유지한다. 설치 파일, 체크섬과 설치 절차를 제공한다.
- [ ] 모의 CLI로 Windows와 Linux에서 작업 접수, 추가 지시, 창 종료·재연결, 테스트·리뷰, 데이터 호환을 검증한다. 설치 파일 실행과 인증된 실제 작업은 각각 별도 증거를 남긴다.
- [ ] 별도 브랜치의 PR을 리뷰하고 필수 Windows·Linux CI를 통과한 정확한 커밋을 병합한다. 현재 서비스 연결은 기존 서비스를 사용하며 운영 권한과 안정 배포는 기존 절차를 따른다.

## 실패 시 동작

포트에 다른 프로그램이 실행 중이면 기존 설정을 보존하고 연결 오류를 보여준다. 로컬 실행기 정보가 오래됐으면 현재 부팅 응답을 먼저 확인한다. 저널은 기존 Studio 소유권 규칙으로 보호하며, 부팅 중 충돌한 실행기는 오류를 반환한다. 재부팅이나 실행기 종료로 중단된 실행은 기존 Studio 복구 규칙을 따른다. CLI 준비 상태는 해당 작업 호스트의 고정된 진단 결과로 표시한다.
