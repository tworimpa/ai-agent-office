# AO-002A Local Observer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking. One independent whole-branch review follows implementation.

**Goal:** 한국어 로컬 화면에서 최근 작업·선택 상세·단계 이벤트를 관찰한다.
**Architecture:** Python stdlib loopback HTTP server가 existing SQLite를 readonly로 읽고 패키지 assets를 제공한다. Vanilla ES modules가 serial polling, 선택 보존과 seq cursor를 관리한다.
**Tech Stack:** Python 3.11+, sqlite3, http.server, HTML/CSS/JS; pytest와 Node built-in test runner.
**Spec:** [AO-002 설계](../specs/2026-11-06-ao-002-observer-design.md). 사용자의 '진행'으로 승인된 관찰 화면 범위이며, 세부 기술 선택은 구현자의 선택으로 기록한다. Builder check: 중요한 미결 질문 없음.

## Global Constraints

- Windows/Linux, Python 3.11/3.13. 기존 stable DB/source와 분리.
- Readonly TaskStore만 사용. worker/recovery/cancel/mutation API 없음. bind=127.0.0.1 고정.
- GET/HEAD 고정 routes/assets; POST/PUT/PATCH/DELETE/OPTIONS=405. 외부 Host/Origin API 차단, CSP/no-store/nosniff 적용.
- 최근 task 200건, events limit 기본100/최대500, cycle 최대10페이지, 표시 최근1000개.
- 3초 serial poll, fetch timeout10초, hidden pause, selection generation으로 stale 응답 폐기, textContent 렌더링.
- 새 dependency/원격 hosting 없음. Assets를 wheel에 포함.

## Review Focus

1. 단순 조회가 DB를 만들거나 worker를 실행하는 경우.
2. URL/path/Host/Origin을 이용한 임의 파일 또는 외부 페이지의 DB 읽기.
3. 선택 전환·run 변경·중복 페이지·느린 응답으로 다른 task 이벤트가 섞이는 경우.
4. 자동 갱신으로 keyboard focus가 사라지거나 모바일 가로 overflow가 생기는 경우.
5. 서버/DB 장애의 오래된 데이터를 현재 성공 상태로 보이는 경우.

## Task 1: Readonly HTTP surface와 CLI

Files: create `src/agent_office/observer.py`, `tests/test_observer.py`; modify `cli.py`.
Interface: `ObserverServer(db_path: Path, port: int=8765)` context manager exposes `server_address`, `serve_forever`, `shutdown`; `serve(db_path: Path, port: int)->None` prints the loopback URL and runs until Ctrl+C.

- [ ] 먼저 real HTTP 테스트: task list/detail/events cursor, missing/invalid DB no-create, wrong ID/query/duplicate query, Host/Origin/405/404/path traversal, DB removal after startup.
- [ ] pytest RED 확인 후 server를 구현. 고정 assets는 다음 task에서 채운다. raw exception/URL 로그 금지.
- [ ] CLI `serve --port`를 연결하고 serve가 다른 run 분기에 들어가지 않는지 검증. 전체 pytest 후 commit.

## Task 2: 순수 상태 모델과 한국어 화면

Files: create `web/state.js`, `web/app.js`, `web/index.html`, `web/style.css` under `src/agent_office/`; `tests/web/state.test.mjs`; package-data in `pyproject.toml`.
Interfaces: `mergeEvents(current, page, runId)->{runId,events,cursor}`, `stateLabel(state)->string`; merge는 입력 배열을 변이하지 않고 run 변경 시 reset, seq 오름차순 dedup, 최대1000개, 빈 page에서 cursor 유지.

- [ ] Node test RED: 중복/reordered seq, 새 run reset, 빈 page cursor, 1000개 상한, 계획/승인 label 구분.
- [ ] state helpers 구현 후 Node GREEN. native button/label/heading/list, focus-visible과 responsive Grid로 화면 구현.
- [ ] serial poll/abort/generation/hidden pause를 연결. 전체 pytest+Node tests, asset MIME/header/content 및 wheel inclusion 확인 후 commit.
