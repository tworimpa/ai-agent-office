# 안정 소스 배포·재시작 구현 계획

안정 버전 원장이 승인한 소스를 호스트별 관리 대상 Studio 서비스에 배포한다. 소스의 승격·롤백과 실제 서비스의 배포 기록은 독립적으로 보존한다.

1. 운영자 전용 배포 디렉터리에 릴리스 ID, 대상 ID, 호스트의 기존 서비스 이름·고정 루프백 포트·런타임 저널 ID를 등록한다. 선택한 안정 버전의 커밋에서 독립 소스 슬롯을 만들고 재시작 전에 내용을 검사한다.
2. 서비스 계정용 런처는 읽기 전용 슬롯에서 Studio를 실행한다. 루프백 상태 응답에 실제 부팅 ID, 적용한 배포 요청, 소스 순번·SHA와 저널 식별자를 포함한다. 운영자가 설정한 OS 서비스 관리자만 서비스 수명주기를 제어한다.
3. 터미널에서 대상 서비스, 선택한 순번, 실제 실행 버전, 재시작 영향을 검토하고 확인한다. 직전 정상 버전을 저장한 뒤 포인터 전환, 재시작, 새 프로세스의 응답 검사를 수행한다. 실패하면 직전 소스로 전환해 다시 기동하고 복구 확인 결과를 기록한다. 중단된 작업은 같은 대상에 대한 복구 절차로 수습한다.
4. 로컬·SSH 작업실의 안정 버전 화면에서 선택한 버전과 서비스의 실제 응답을 비교한다. 설정 없음, 확인 실패, 배포 실패와 복구 실패를 구분한다. 웹과 SSH에는 배포·재시작 변경 경로를 두지 않는다.
5. 운영 서비스와 분리한 임시 대상에서 성공·부팅 실패·복원·잘못된 대상·중복 요청·중단을 시험한다. Windows와 Linux, 브라우저, 전체 PR CI와 병합 커밋을 확인한다.
