# 2단계 구현 계획 · 역할별 엔진과 호스트별 검증

로컬 또는 원격 작업실에서 개발자와 리뷰어를 각각 고른다. 기본값은 Codex와 Antigravity로 유지하고, Claude Code, Gemini CLI, Cline CLI를 같은 역할 선택 목록에 제공한다. [제품 구상](../../product-vision.md)

| 작업 | 구현 결정 | 확인 방법 |
| --- | --- | --- |
| CLI 어댑터 | Gemini와 Cline의 공식 비대화형 입력·구조화 출력 규약을 사용한다. 계획·리뷰와 수정 모드를 구분한다. | 모의 CLI로 표준입력, 권한 옵션, 완료·오류 응답을 검증한다. |
| 실행 배정 | 요청에 개발자·리뷰어를 기록하고 작업 저널의 역할별 엔진을 실제 그래프에서 사용한다. | 기본 요청·이전 실행 재조회, 원격 접수 응답 유실 후 동일 ID 재전송, 역할 변경 충돌을 검사한다. |
| 호스트별 근거 | 호스트가 CLI 설치·버전·비대화형 옵션과 별도 예제 검증의 읽기·수정·리뷰 결과를 제공한다. 검증에는 해당 호스트·실행파일·버전·시각을 연결한다. | 설치 정보만으로 실작업이 통과하지 않고, 다른 호스트 또는 변경된 실행파일의 근거가 섞이지 않는지 검사한다. |
| 작업실 화면 | 선택한 호스트의 엔진 목록과 검증 내역을 표시하고 신규 실행 및 재접속에서 역할 배정을 보존한다. | 두 호스트에서 다른 엔진 조합과 근거를 표시하고 실제 요청·결과의 배정을 대조한다. |

검증용 제공자 호출은 운영자가 실행 호스트에서 별도로 시작한다. 설치·로그인이나 화면 조회를 계기로 실제 모델을 호출하지 않는다. 자동 테스트는 임시 예제와 모의 제공자 프로세스를 사용한다.

## 구현과 검증 경로

- 기존 저널의 개발자·리뷰어 열을 실행 목록과 상세에 연결한다. 기본 조합은 이전 요청 해시를 유지하고, 다른 조합은 두 역할을 포함해 해시를 계산한다. [역할 배정과 재접수 테스트](../../../tests/test_studio_engines.py)
- Gemini와 Cline은 ACP v1으로 새 세션을 열어 역할에 맞는 모드를 설정한다. Cline의 일회성 파일 권한은 규약을 확인한 CLI 3.0.74에 한정한다. [어댑터 규약과 버전 근거](../../engine-protocols.md) · [프로토콜 테스트](../../../tests/test_acp_adapters.py)
- 선택한 호스트가 진단과 검증 내역을 제공한다. `verify-engine`은 임의 참조 값을 가진 예제를 실행하고 파일·판정·종료 상태를 검사한다. 원격 저널을 조회할 때도 같은 호스트·실행 환경·버전·어댑터 규약에 귀속된 근거만 표시한다. [검증 기록 테스트](../../../tests/test_engine_evidence.py)
- 브라우저 수동 시험에서는 Windows 작업실에 Claude Code 개발자와 Antigravity 리뷰어를, 같은 PC의 WSL 작업실에 Gemini 개발자와 Cline 리뷰어를 배정했다. Edge와 Windows OpenSSH로 원격에 연결해 서로 다른 역할·검증 기록, 작업 결과, 재접속을 확인했다. 시험에는 임시 SSH 계정과 모의 제공자 실행 파일을 사용했다. [화면 회귀 테스트](../../../tests/web/studio.test.mjs)
