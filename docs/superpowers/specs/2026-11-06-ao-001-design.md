# AO-001 작업 저장과 이벤트 기록 설계안

상태: 사용자 검토용 제안. 구현은 시작하지 않았다.
기준: 2026-11-06, `main`의 `c82482e2326ef6619cf6b15c15ad73793438389c`.
요구사항: [Issue #2](https://github.com/tworimpa/ai-agent-office/issues/2), [인수인계](../../CODEX_HANDOFF_2026-11-06.md), [기존 구조](../../architecture.md).

## 목적과 현재 상태

현재 CLI는 Git worktree에서 Developer → Test → Reviewer를 실행하지만, 종료하면 작업 상태와 실행 이력을 다시 조회할 수 없다. AO-001은 이 흐름에 영속 기록을 붙여 어떤 작업이 어디까지 진행됐고 왜 멈췄는지 확인하게 한다. 중단된 외부 작업을 자동으로 반복하는 기능은 만들지 않는다.

PR #1은 사용자의 머지 지시로 `main`에 반영됐다. 머지 결과의 로컬 테스트는 Windows Python 3.11과 WSL Python 3.14에서 각각 18개 통과했다. PR head의 CI는 Windows/Ubuntu × Python 3.11/3.13에서 성공했다. 실제 Claude/Codex 모델 호출 및 편집 모드는 미검증이며, 이번 머지는 그 검증이나 무인 운영 승인으로 해석하지 않는다. 과거 handoff/verification의 Draft 표기는 당시 기록이다.

## 기존 합의와 이번 제안

기존 합의는 Windows/Linux 동등 지원, Python 3.11+, LangGraph 외부 조정, Claude/Codex worker, SQLite tasks/events, 사람의 머지·배포 결정이다.

이번에 제안하는 세부 선택은 아래와 같다. 아직 사용자 승인으로 간주하지 않는다.

| 접근 | 장점과 비용 | 제안 |
|---|---|---|
| 별도 SQLite task/run/event 저장소 | 현재 CLI에 붙이기 쉽고 외부 실행의 시작·종료를 명시할 수 있다. 기록 트랜잭션을 직접 관리한다. | AO-001에 사용 |
| LangGraph checkpoint를 작업 DB로 사용 | 그래프 상태 재개에는 유용하지만 외부 CLI 재실행 및 작업 조회 모델을 별도로 다뤄야 한다. | 자동 resume와 함께 후속 검토 |
| 지금 API 서버와 UI까지 구현 | 화면으로 확인할 수 있지만 DB·복구 계약과 서버 수명을 동시에 검증해야 한다. | 이번 단계에서 제외 |

## 범위

- `tasks`, `runs`, `events`를 SQLite 파일에 저장한다.
- 기존 실행 흐름의 단계 시작·성공·실패·재시도·최종 결과를 기록한다.
- `tasks list`, `tasks show`, cursor 기반 `events` 조회를 제공한다.
- 명시적 `recover --run-id`는 소유자가 없는 실행을 `RECOVERY_REQUIRED`로 표시한다.
- 원본 stable 저장소와 개발 후보 worktree/DB를 분리한다.
- 기존 리뷰 판정 충돌 및 Git 오류 보고를 회귀 테스트로 보완한다.

화면, HTTP/WebSocket 서버, 질문 자동 응답, 다른 CLI 엔진, 자동 작업 큐 소비, vendor tool-call 실시간 수집, 세션 자동 resume, 자동 재실행·머지·배포는 포함하지 않는다. 서버가 없으므로 이번 단계에 포트는 없다.

## 저장 계약

`sqlite3` 표준 라이브러리를 사용하고 신규 런타임 의존성은 추가하지 않는다. schema version은 `PRAGMA user_version=1`이다. 더 높은 버전은 수정 없이 거절한다. 초기 DB/schema 생성은 단일 트랜잭션으로 완료한다. 연결에는 `foreign_keys=ON`, `busy_timeout=5000`을 적용하고 기본 rollback journal을 사용한다.

| 테이블 | 필수 필드 |
|---|---|
| tasks | task_id, project, request_snapshot, developer_engine, reviewer_engine, workspace, branch, state, outcome, attempts, max_attempts, current_run_id, created_at, updated_at |
| runs | run_id, task_id, host_name, owner_token, state, outcome, attempts, started_at, ended_at, next_seq |
| events | run_id, seq, operation_key, event_type, role, engine, timestamp, payload_json |

IDs는 생성 시 UUID hex 32자리로 고정한다. 시간은 UTC ISO 8601이다. `(run_id, seq)`와 `(run_id, operation_key)`는 각각 UNIQUE다. 동일 operation_key의 동일 요청은 기존 event를 반환하고 상태/attempt/seq를 다시 증가시키지 않는다. 동일성은 최종 sanitized payload뿐 아니라 event_type/role/engine 및 목표 state/outcome/attempts 전체를 비교한다. 내용이 다른 재전송은 거절한다.

event_type은 RUN_CREATED/WORKSPACE_READY/STAGE_STARTED/STAGE_COMPLETED/STAGE_FAILED/RETRY_SCHEDULED/RUN_FINISHED/RECOVERY_REQUIRED 중 하나다. operation_key는 run_id, attempt, phase, event_type에서 만든 128자 이하 ASCII이며 사용자 요청 원문을 넣지 않는다.

상태 갱신, attempt 갱신, seq 할당, event 추가는 하나의 짧은 `BEGIN IMMEDIATE` 트랜잭션이다. Git·모델·테스트 실행 중에는 DB 트랜잭션을 유지하지 않는다. 동일 task에 다른 active run을 시작하는 것은 거절한다. 이번 버전에는 기존 task의 재실행 진입점을 제공하지 않는다.

DB를 열거나 조회하는 행위는 복구를 실행하지 않는다. 읽기 명령은 SQLite URI `mode=ro`와 `query_only=ON`을 사용한다. DB가 없으면 생성하지 않고 명확한 오류를 반환한다.

## 상태와 결과

| 기존 결과/상황 | 저장 state | outcome |
|---|---|---|
| 생성됨 / Developer / Test / Reviewer | QUEUED / RUNNING / TESTING / REVIEWING | null |
| PLAN_ONLY | PLAN_ONLY | PLAN_ONLY |
| 테스트·리뷰 승인 | READY_FOR_HUMAN_REVIEW | APPROVED |
| Developer 실패 | FAILED | DEVELOPER_FAILED |
| 테스트 실패, 재시도 소진 | FAILED | TEST_FAILED |
| Reviewer 실행 실패 | FAILED | REVIEW_FAILED |
| 수정 요구, 재시도 소진 | FAILED | CHANGES_REQUESTED |
| 판정 없음 또는 상충 | WAITING_USER | REVIEW_UNDECIDED |
| 외부 실행 전 취소 / 전체 종료 확인 | CANCELED | CANCELED |
| 실행 소유자 상실·종료 여부 불명 | RECOVERY_REQUIRED | INTERRUPTED |

`PLAN_ONLY`는 테스트나 리뷰 통과를 뜻하지 않는다. 기존 CLI JSON의 `status` 의미를 유지하면서 task_id/run_id/state/outcome을 추가한다. `WAITING_USER`는 확인이 필요하다는 기록이며 이번 단계에 응답/재개 기능은 없다.

active state는 QUEUED/RUNNING/TESTING/REVIEWING이다. QUEUED는 RUNNING으로, RUNNING은 TESTING 또는 PLAN_ONLY로, TESTING은 REVIEWING 또는 재시도 RUNNING으로, REVIEWING은 재시도 RUNNING 또는 READY_FOR_HUMAN_REVIEW/WAITING_USER로 전이한다. active state에서는 FAILED/CANCELED/RECOVERY_REQUIRED로도 전이할 수 있다. 같은 state의 단계 메타데이터 event는 허용한다. terminal state에서 새 실행/전이는 거절하며, 기존 operation_key의 동일 재전송은 예외적으로 기존 event만 반환한다.

## 외부 실행과 복구

지원 범위는 단일 호스트의 로컬 디스크 DB다. Windows/WSL은 각자의 DB를 사용한다. 네트워크 파일시스템이나 호스트 간 동일 DB 공유는 지원하지 않는다.

각 run의 고정 sidecar lockfile에 Linux `fcntl.flock(LOCK_EX|LOCK_NB)`, Windows `msvcrt.locking(LK_NBLCK, 1)`을 사용한다. 잠금은 run 생성 전부터 최종 DB commit까지 유지하고 FD/handle은 자식에게 상속하지 않는다. lockfile을 삭제하거나 교체하지 않는다. 잠금 파일 이름은 검증된 run_id로만 만든다.

실행 순서는 다음과 같다.

1. run_id와 worktree 경로/브랜치를 결정하고 run 잠금을 획득한다.
2. task/run/workspace intent 및 `RUN_CREATED`를 commit한다.
3. worktree를 생성하고 `WORKSPACE_READY`를 기록한다.
4. 단계 시작 event commit → 외부 작업 → 완료/실패 event commit 순서로 실행한다.
5. 최종 결과 commit 후 잠금을 해제한다.

시작 기록이 실패하면 외부 작업을 실행하지 않는다. 결과 기록이 실패하면 다음 외부 단계로 넘어가거나 성공을 보고하지 않는다. Git worktree 생성 직후 중단돼도 기존 intent로 그 경로를 찾을 수 있다.

`recover`는 같은 host_name인지 확인하고 nonblocking 잠금을 획득한 다음, 트랜잭션 안에서 state를 다시 읽는다. active state에만 복구 표시를 추가하고 terminal state는 그대로 둔다. 살아 있는 owner의 잠금을 얻지 못하면 상태를 바꾸지 않는다. PID만으로 생존 여부를 결정하지 않는다.

coordinator가 죽어도 vendor 자식 프로세스는 남을 수 있다. `RECOVERY_REQUIRED`는 종료나 롤백의 증거가 아니다. 복구 명령은 worker/Git/test를 실행하거나 자식을 kill하지 않는다. Ctrl+C/timeout에서 자식 전체 종료가 증명되지 않으면 `CANCELED`로 단정하지 않는다.

AO-001에서는 adapter returncode 124와 테스트 subprocess TimeoutExpired를 보수적으로 모두 RECOVERY_REQUIRED/INTERRUPTED로 처리한다. 남은 retry budget과 관계없이 추가 worker/test/reviewer 호출을 하지 않는다. 기존 테스트 timeout의 TEST_FAILED 자동 retry 경로도 이 정책으로 바꾼다.

## 기록 최소화와 보관

이벤트 payload의 허용 키는 phase, state, attempt, role, engine, returncode, outcome, duration_ms, truncated다. state/outcome/attempt는 저장 전이와 일치해야 한다. 원본 prompt, source, stdout/stderr, 환경변수, provider session/token은 이벤트에 저장하지 않는다. workspace 전체 경로는 task의 로컬 작업 메타데이터로만 저장한다.

phase는 run/workspace/developer/test/review, role은 developer/tester/reviewer, engine은 claude/codex 또는 null이다. state/outcome은 위 상태 표의 값만 사용한다. attempt/duration_ms는 0 이상 정수, returncode는 정수, truncated는 bool이다. 허용 키 안에 dict/list나 임의 문자열을 넣어 우회하는 것은 거절한다.

사용자가 입력한 요청은 알려진 token/API key/Authorization 패턴을 마스킹한 `request_snapshot`으로 저장하며 UTF-8 8,192 bytes 이내다. 회귀 입력에는 API_KEY/TOKEN/SECRET/PASSWORD 이름의 할당, Authorization Bearer, sk-/sk-ant-/ghp_/github_pat_ 형식 값을 포함한다. 원문은 현재 실행 메모리에만 보존하고 snapshot을 재실행 입력으로 사용하지 않는다. 임의의 자연어에 포함된 모든 비밀을 자동 탐지한다고 보장하지 않는다.

JSON payload 전체는 UTF-8 16,384 bytes 이내다. 미허용 키는 저장 전에 제거하고, 허용 키에 잘못된 값 타입/도메인이 있거나 최종 JSON이 한도를 넘으면 저장 전 ValueError로 거절한다. request_snapshot만 마스킹 후 UTF-8 문자 경계를 지켜 축약하며, 생략 표시를 포함한 총 길이를 8,192 bytes 이내로 제한한다. 이 한도는 영속 기록에 대한 것으로 기존 subprocess 전체 메모리 사용의 상한을 뜻하지 않는다.

자동 삭제는 없다. events는 애플리케이션 실행 중 append-only다. 사용자가 모든 실행이 멈춘 것을 확인한 뒤 DB를 통째로 보관/교체하는 절차를 문서화한다. 무인 운영 전에 별도의 전체 DB 용량/보관 및 subprocess 출력 제한 정책을 검토한다.

## CLI와 환경 분리

전역 `--db PATH`는 subcommand 앞에 둔다.

```text
agent-office --db <candidate-db> run --repo <candidate-repo> --task ...
agent-office --db <db> tasks list --limit 50
agent-office --db <db> tasks show <task_id>
agent-office --db <db> events <task_id> --run-id <run_id> --after-seq 0 --limit 100
agent-office --db <db> recover --run-id <run_id>
```

tasks list 기본/최대 limit=50/200, events 기본/최대=100/500, after-seq는 0 이상이다. task/run 연결이 다르거나 ID/범위가 잘못되면 오류다. run-id 생략 시 task의 current_run_id를 선택한다. JSON 출력을 기본으로 하며 events는 seq > after-seq를 seq 오름차순으로, tasks는 updated_at 내림차순 후 task_id 오름차순으로 조회한다.

기본 DB는 Windows `%LOCALAPPDATA%\AI-Agent-Office\stable\tasks.sqlite3`, Linux `${XDG_STATE_HOME:-~/.local/state}/ai-agent-office/stable/tasks.sqlite3`다. 후보 개발은 별도의 명시적 `--db`를 사용한다. CLI가 DB를 복사하거나 stable로 승격하지 않는다. doctor는 DB를 열지 않는다.

## 완료 조건과 개발 순서

1. 리뷰 판정과 Git 오류의 기존 경계 보완.
2. SQLite 저장 계약과 이벤트 필터/한도.
3. run 잠금과 명시적 복구.
4. 현재 실행 흐름과 원자적 기록 연결.
5. 조회 CLI와 운영 문서, 기존 Windows/Linux CI 통과.

재시작 보존, 트랜잭션 rollback, idempotency, 동시 claim, 살아 있는 run 보호, fake worker 중단 후 실행 횟수 불변, DB 장애 시 외부 호출 중지, 한글·공백 경로/byte 한도, 조회 무부작용, stable/candidate 분리를 테스트한다. 실제 모델 호출·편집 수용 검증은 계속 별도 항목으로 남긴다.

## 설계 근거

- [Python sqlite3](https://docs.python.org/3/library/sqlite3.html): 파일 DB, 트랜잭션과 URI 읽기 연결.
- [Windows msvcrt.locking](https://docs.python.org/3/library/msvcrt.html#msvcrt.locking), [Unix flock](https://docs.python.org/3/library/fcntl.html#fcntl.flock): 플랫폼별 nonblocking 파일 잠금.
- [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts): 그래프 중단/재개와 외부 부작용의 구분. 이번 설계는 checkpoint 자동 재개를 사용하지 않는다.
