# Bot Definition 1.0

Bot Definition은 한 봇의 이름, 자유롭게 정한 역할, 지침과 참고 파일을 하나의 UTF-8 JSON 문서로 교환하는 형식이다. 예를 들어 디자인 도구에서 만든 리서처 봇을 Office에 가져오면 역할 이름과 인터뷰 스킬, 빈 노트 폴더를 그대로 사용할 수 있다. 데스크톱, 웹, CLI 작성기는 같은 문서를 읽고 쓸 수 있다. [완성된 다온 봇 예제](../src/agent_office/examples/research.bot.json)

## 처음 쓰는 작성자

아래 내용을 UTF-8로 저장하면 가져올 수 있는 최소 봇이 된다.

~~~json
{
  "specVersion": "1.0",
  "id": "ux-researcher",
  "name": "다온",
  "role": "사용자 경험 리서처",
  "files": {
    "SOUL.md": "관찰한 행동과 참가자의 말을 구분해 기록한다."
  }
}
~~~

첫 명령은 Workspace나 네트워크 연결 없이 파일을 검사한다. 나머지 명령에서는 Studio가 사용하는 저널 경로와 등록한 Workspace ID를 지정한다. 내보낼 경로를 생략하면 JSON이 표준 출력으로 나온다. UTF-8 파일을 직접 만들 때는 새 파일명을 지정한다.

~~~shell
agent-office bots validate --file daon.bot.json
agent-office --db tasks.sqlite3 bots import --workspace-id WORKSPACE_ID --file daon.bot.json
agent-office --db tasks.sqlite3 bots export --workspace-id WORKSPACE_ID --id ux-researcher --output daon-copy.bot.json
~~~

## 작성기와 판독기의 계약

**버전과 검증.** 1.0 문서는 아래 구조와 경로·텍스트·용량 규칙을 모두 만족해야 한다. 구조 검증용 JSON Schema는 Draft 2020-12이며 버전별 파일명과 고유 ID를 사용한다. 편집기는 문서에 선택 필드 `$schema`를 넣어 자동 완성에 활용할 수 있다. 판독기는 배포본의 스키마를 로컬에서 사용해도 된다. 계약이 달라지면 별도 버전과 스키마 ID를 발행한다. 판독기는 지원하지 않는 버전을 명시적으로 거부한다. [1.0 JSON Schema](../src/agent_office/schemas/bot-1.0.schema.json) · [JSON Schema Draft 2020-12](https://json-schema.org/draft/2020-12)

| 필드 | 형식과 동작 |
| --- | --- |
| `specVersion` | 필수. 문자열 `"1.0"`. |
| `id` | 필수. 최대 64자. 영문 소문자·숫자 단어를 하이픈 하나로 이어 쓴다. |
| `name`, `role` | 필수. 각 40자·60자 이내의 한 줄, 앞뒤 공백과 제어문자 없이 작성한다. `role`은 작성자의 말로 정한다. |
| `files` | 필수. 경로를 키, 파일 전문을 문자열 값으로 갖는 객체. 루트의 `SOUL.md`를 포함해 최대 32개다. |
| `folders` | 선택. 명시적으로 보존할 디렉터리 경로 최대 32개. 생략하면 빈 배열이다. 자식 경로에 나타난 부모 디렉터리는 자동으로 생긴다. |
| `extensions` | 선택. 네임스페이스와 그 값의 객체. 생략하면 빈 객체다. |
| `$schema` | 선택. 값은 이 버전 스키마의 `$id`다. |

문서의 최대 크기는 BOM 없는 UTF-8 512 KiB다. JSON 객체에서 중복 키를 거부한다. 선언된 필드만 최상위 수준에 둘 수 있다. 비교할 때 객체 키와 명시적 폴더 목록의 순서는 무시한다. 텍스트의 줄 끝, 파일 경로의 대소문자, 확장 값 내부 배열의 순서는 보존한다. 판독기는 누락된 선택 필드의 기본값과 스키마 ID를 내보낼 때 채울 수 있다.

**파일과 폴더.** 각 경로는 NFC로 정규화된 유니코드 상대 경로이며 구분자는 `/`다. 전체는 UTF-8 240바이트 이내, 각 구성 요소는 128바이트 이내, 깊이는 최대 8단계다. 이름의 끝에 공백이나 점을 쓸 수 없다. 빈 구성 요소, `.`, `..`, `.git`, 역슬래시, `< > : " | ? *`, 유니코드 제어·서식 문자, 줄·문단 구분자와 서로게이트 문자를 거부한다. Windows 장치명(CON, PRN, AUX, NUL, CONIN$, CONOUT$, COM1~9, LPT1~9와 위첨자 ¹²³의 해당 표기)은 확장자가 붙어도 사용할 수 없다. 판독기는 모든 부모 경로까지 유니코드 대소문자 접기(case folding)로 비교한다. `Skills/a`와 `skills/b`, 파일 `a`와 디렉터리 `a/b`를 함께 쓸 수 없다. 같은 명시적 디렉터리의 중복 선언도 거부한다. 루트의 메모 파일 이름은 `MEMORY.md`를 사용한다.

파일 하나는 UTF-8 8 KiB 이내의 텍스트이며 `SOUL.md` 이외 파일의 합계는 24 KiB 이내다. 텍스트에는 탭·CR·LF 이외의 제어문자를 넣을 수 없다. 빈 파일도 보존한다. `SOUL.md`는 기본 업무 지침이다. `AGENTS.md`, `skills/interview/SKILL.md`, `mcp/servers.json`, `hooks/events.json` 등은 작성자가 이름과 내용을 정하는 가상 파일이다. 디렉터리를 명시하면 안에 파일이 없어도 유지된다. 소비자는 가져오기 단계에서 파일을 데이터로 취급한다. 경로는 실제 호스트 폴더, 원격 URL, 실행할 명령을 가리키지 않는다.

**확장.** 확장 이름은 영문 소문자로 시작하는 레이블을 점으로 이어 붙인 역도메인 형식이다. 레이블에는 영문 소문자·숫자·하이픈을 쓸 수 있다. 이름은 최대 128자, 레이블은 둘 이상, 확장은 최대 16개다. 값에는 문자열, 유한한 숫자, 불리언, null, 배열, 객체를 사용할 수 있다. `extensions` 객체 자체를 깊이 0으로 계산해 최대 16단계까지 허용한다. 전체 확장을 공백 없는 UTF-8 JSON으로 인코딩한 크기는 160 KiB 이내다. 판독기는 모르는 확장의 값도 보관해 다음 내보내기에 포함한다. 런타임 연결, 도구 실행, 권한 승인은 소비자가 호스트 정책에 따라 별도로 처리한다.

### Office 외형 확장

`io.github.tworimpa.agentoffice.appearance`는 선택한 캐릭터의 표시 정보다. `preset`은 필수이며 0~11의 정수다. `image`를 생략하면 해당 프리셋을 표시한다. 지정할 때는 정확한 접두사 `data:image/webp;base64,` 뒤에 표준 Base64 인코딩을 쓴다. 이 버전의 확장에는 두 필드만 사용할 수 있다. 예제의 프리셋을 이해하지 못하는 클라이언트도 자체 아이콘으로 봇을 표시하고 저장된 확장을 보존할 수 있다.

이미지는 1~512픽셀 너비·높이, 원본 96 KiB 이내의 정적 WebP다. 1.0 판독기는 RIFF 길이, 청크 범위, 이미지 헤더의 크기를 검사한다. 단일 VP8/VP8L 이미지 또는 투명도가 있는 VP8X 이미지(VP8L 혹은 ALPH와 VP8)를 허용한다. 애니메이션·메타데이터 청크, 외부 URL, SVG와 다른 MIME 형식은 거부한다. 화면 표시는 해당 클라이언트 이미지 디코더가 담당한다. [WebP 컨테이너 규격](https://developers.google.com/speed/webp/docs/riff_container)

## Office 어댑터

Office는 Workspace별로 봇을 설치한다. 같은 ID와 동일한 정의를 다시 가져오면 기존 봇을 돌려준다. 다른 정의가 같은 ID를 사용하면 충돌을 반환한다. 사용자 봇에는 비어 있지 않은 `SOUL.md`가 필요하다. `office-coordinator`, `office-developer`, `office-reviewer`는 기본 정의용 ID다. 기본 정의의 동일한 사본은 다시 가져올 수 있다.

가져온 JSON의 파일·폴더·확장은 SQLite에 보관한다. 설치만으로 MCP 서버나 훅이 실행되거나 호스트의 설정 파일이 생성되지 않는다. Office는 배정에 쓰는 엔진과 권한을 Workspace에서 선택하고, 실행을 시작할 때 사용할 봇 정의의 사본과 해시를 고정한다. 담당자의 지침과 Markdown·텍스트 참고 자료는 명령 문맥에 들어간다. mcp/와 hooks/의 파일 및 기타 실행·설정 자원은 보관하고 내보내며 공급자 프롬프트에서 제외한다. 외형, 확장 값, 빈 폴더는 프롬프트에 넣지 않는다.

로컬 저장 버전 1·2로 표현 가능한 봇은 예전 저장 표현과 SHA-256 해시를 유지한다. 중첩 경로·명시적 폴더·확장 등이 필요한 봇은 로컬 저장 버전 3을 사용한다. 로컬 버전과 해시는 공개 형식의 버전과 별도로 관리한다. 키가 없는 `MEMORY.md`는 Office 편집기에서 빈 메모로 열리며 사용자가 저장한 뒤에 내보내기 파일에 포함된다. 이전 저장소가 허용하던 이름 중 Windows 장치명 등 이 형식에서 사용할 수 없는 경로는 내보내기 검사에서 오류를 보고한다. 기존 실행에 고정한 정의는 당시 형식으로 읽는다.

참조 구현 및 적합성 테스트는 같은 스키마와 예제에 대해 오프라인 검사, 설치·내보내기 왕복, 대소문자와 경로 충돌, 파일 크기, 확장 보존, 과거 실행 해시를 검사한다. [검증기](../src/agent_office/bot_spec.py) · [적합성 테스트](../tests/test_bot_spec.py)
