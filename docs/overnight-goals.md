# 장시간 개발 목표

Workspace에서 조정자에게 파일 수정을 허용하고 장시간 개발 목표를 선택한다. “Windows에서 설정이 사라지는 문제를 재현하고 수정한 뒤 전체 회귀까지 확인해 줘”처럼 요청한다. 작업공간 설정에 저장한 정책을 접수 시점에 복사한다. 완료 기준·기준 커밋·선택한 폴더·검증 예산은 목표 기록에서 확인한다. 같은 요청 ID를 재전송하면 기존 접수 결과가 돌아온다.

## 실행과 검증

작업공간 설정에서 빠른 확인, 전체 회귀, 설치판 여정의 호스트·명령·제한 시간·성공 조건을 선택한다. 기본 활성 시간은 8시간이고 최대 개발 시도는 6회다. 기본 전체 회귀는 pytest이고 제한 시간은 2시간이다. **AI Agent Office** 프리셋은 Python, 웹 테스트, 설치판 여정을 함께 확인한다. 검증은 해당 호스트의 일반 사용자 실행 환경에서 수행한다.

- 기준 커밋의 실패를 기록한 뒤 수정한다. 사용자 결정이 필요하거나 계획을 확인하기로 한 업무는 회의를 연다. 수정 시도마다 검증하고 더 나은 후보와 근거를 남긴다. 지정 호스트가 연결되지 않았거나 출력·환경·범위를 확인하지 못한 단계는 보고서에 표시한다.
- 재현이 필요한 Python 버그가 기존 검사에서 드러나지 않으면 개발자가 새 pytest 회귀 테스트를 작성한다. 작업실은 깨끗한 원본 커밋에 그 테스트만 넣어 실패를 직접 확인하고, 이후 후보에서 같은 테스트를 다시 실행한다. 원본 코드 변경 없이는 실패를 재현할 수 없으면 조건을 확인할 수 있도록 그 지점에 기록을 남긴다.
- 웹 테스트에는 호스트의 Node 및 프로젝트 잠금 파일과 일치하는 의존성이 필요하다. 설치판 여정은 실제 호스트 설치 파일과 후보 소스의 일치 여부를 확인한다. 설치판 또는 호스트 검증 도구가 없으면 그 결과는 미검증이다. 설치형 실행기에서 개발용 도구를 다른 경로에 준비할 때는 `AGENT_OFFICE_GOAL_WEB_PROJECT`와 `AGENT_OFFICE_GOAL_INSTALL_HARNESS`로 검증 호스트의 준비된 체크아웃과 여정 스크립트를 지정한다.
- 다른 호스트에서 검증하려면 등록한 SSH Studio와 그 호스트의 운영자가 준비한 소스를 사용한다. 각 영수증에 요청한 호스트, 실제 실행 위치, 명령과 종료 코드가 남는다. [원격 검증 준비](goal-peer-checks.md)

### 프로젝트 테스트 선택

각 단계에서 Python pytest, Node.js npm test, Rust cargo test, Go go test를 선택할 수 있다. 실행 호스트와 제한 시간은 단계마다 저장한다. npm 프로젝트는 직접 지정으로 `npm run test:unit` 같은 이름도 등록할 수 있다. 각 인수를 줄 단위로 입력한다. 기존 Office 프리셋의 `npm run test:web`은 동봉된 웹 검사를 사용한다. 다른 프로젝트의 동명 스크립트는 `npm --ignore-scripts run test:web`로 명시한다. npm은 준비된 의존성으로 선택한 테스트 스크립트를 실행하고 자동 pre/post 스크립트를 생략한다. Cargo는 커밋된 Cargo.lock과 캐시된 의존성을 사용한다. Go는 로컬 도구와 모듈을 사용한다. 세 명령의 영수증은 명령 전체의 종료 코드와 출력을 기록한다. 개별 테스트를 비교해야 할 때는 JUnit 형식의 호스트 검사를 등록한다.

### 프로젝트 고유 명령

기본 레시피 외에 조직의 빌드 검사나 JUnit 검사를 연결할 수 있다. 실행 호스트 운영자가 프로젝트 작업 트리 밖의 JSON 파일을 작성하고 그 절대 경로를 `AGENT_OFFICE_GOAL_RECIPES`에 설정한다. 예를 들어 아래 설정은 등록한 프로젝트에서만 지정된 프로그램과 스크립트를 사용한다. 경로는 실제 호스트에 맞춰 지정한다.

```json
{
  "acceptance": {
    "project": "/work/my-project",
    "command": ["/usr/bin/python3", "/opt/office-checks/acceptance.py", "{report}"],
    "inputs": ["/opt/office-checks/acceptance.py"],
    "result": "junit"
  }
}
```

`python -m agent_office.goal_host_checks acceptance`는 명령을 실행하지 않고 검증 참조를 출력한다. 출력된 세 인자(`host-check`, 이름, SHA-256)를 작업실 설정의 명령란에 한 줄씩 입력한다. 호스트 실행 파일과 외부 스크립트·설정 등 `inputs`의 내용이 바뀌면 새 참조를 발급한다. `junit`은 지정한 `{report}` 파일의 개별 결과를 수집한다. `exit`는 등록 명령 전체를 한 개의 검사로 기록한다. 비밀 값은 명령 인수나 검증 출력에 넣지 않는다.

## 자리를 비웠다가 돌아왔을 때

사무실에서 해당 목표를 선택해 마지막 진전과 시각, 응답 요청, 완료 기준과 검증 범위를 읽는다. 부분적으로 개선된 후보도 보존된다. 후보 간 변경을 비교한 다음 검증과 독립 리뷰를 통과한 후보를 채택할 수 있다. 채택은 저널에 남는 사용자 결정이다. Git 병합과 운영 배포는 각각의 운영 절차를 따른다.

창을 닫거나 화면과 원격 호스트 사이의 연결이 끊겨도 실행기가 살아 있으면 기존 목표를 다시 연다. 실행기가 중단되면 복구 화면에서 소유권, 마지막 완료 단계, 작업 트리 및 검증 환경, 전달 대기 중인 지시를 확인한다. 재개 가능한 경계에서만 같은 목표를 이어간다. 외부 작업의 완료 여부가 불확실하면 그 근거를 확인한 뒤 조치한다. 질문에 답하거나 권한을 승인하는 대상은 원래 요청으로 고정된다.
